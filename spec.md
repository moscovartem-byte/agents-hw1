# Спецификация трекера

## ADDED Requirements

### Requirement: Автономный файл
Приложение MUST поставляться одним файлом tracker-v2.html
со встроенными CSS и JavaScript.
Оно MUST работать без CDN, внешних библиотек,
внешних ресурсов и API-ключей.

#### Scenario: Автономное открытие
- WHEN файл открывается в обычном браузере без сети
- THEN все обязательные функции доступны.

### Requirement: Начальные данные
При отсутствии сохраненных данных приложение MUST
инициализировать задачи:
«Чтение» — 2 ч, done=true;
«Практика» — 4 ч, done=false;
«Повторение» — 2 ч, done=false.
Начальный фильтр MUST быть «все».

#### Scenario: Начальные показатели
- WHEN загружен начальный пример
- THEN отображаются три задачи, всего 8 ч,
  выполнено 2 ч и прогресс 25%.

### Requirement: Добавление и проверка данных
Приложение MUST добавлять задачу только при корректном вводе.
Название после trim MUST быть непустым.
Часы MUST быть конечным числом от 0,5 до 24 включительно,
кратным 0,5.
Пустое значение часов MUST считаться ошибкой,
а не преобразовываться в ноль.
Новая задача MUST иметь уникальный id и done=false.

При некорректном вводе приложение MUST:
- не добавлять задачу;
- показывать ошибку рядом с соответствующим полем;
- сохранять введенные значения формы.

#### Scenario: Корректное добавление
- WHEN введены непустое после trim название
  и допустимое количество часов
- THEN новая активная задача добавляется в данные,
  а список и показатели обновляются.

#### Scenario: Пустое название
- WHEN название пустое или состоит только из пробелов
- THEN задача не добавляется, рядом с названием видна ошибка,
  значения формы сохраняются.

#### Scenario: Некорректные часы
- WHEN часы пустые, нечисловые, отрицательные,
  меньше 0,5, больше 24 или не кратны 0,5
- THEN задача не добавляется, рядом с часами видна ошибка,
  значения формы сохраняются.

### Requirement: Изменение состояния
Переключение отметки выполнения MUST менять done
соответствующей задачи в данных и обновлять показатели.

#### Scenario: Завершение практики
- WHEN в начальном примере «Практика» отмечена готовой
- THEN выполнено 6 из 8 ч, прогресс равен 75%.

#### Scenario: Отмена завершения
- WHEN отметка «готово» снимается
- THEN done становится false, а показатели пересчитываются.

### Requirement: Удаление
Удаление MUST исключать соответствующую задачу из данных
и обновлять список и показатели.

#### Scenario: Удаление всех задач
- WHEN все задачи удалены
- THEN всего 0 ч, выполнено 0 ч и прогресс 0%,
  без NaN и Infinity.

### Requirement: Прогресс по часам
Приложение MUST рассчитывать прогресс как округление
100 × сумма часов готовых задач / сумма часов всех задач.
При отсутствии задач прогресс MUST равняться 0%.

#### Scenario: Все задачи завершены
- WHEN все существующие задачи отмечены готовыми
- THEN прогресс равен 100%.

### Requirement: Фильтрация
Приложение MUST предоставлять фильтры
«все / активные / готовые».
Фильтр MUST влиять только на видимый список.
Общие часы, выполненные часы и прогресс MUST
рассчитываться по всем задачам.

#### Scenario: Активные задачи
- WHEN в начальном примере включен фильтр «активные»
- THEN видны «Практика» и «Повторение»,
  всего остается 8 ч, выполнено 2 ч, прогресс остается 25%.

#### Scenario: Готовые задачи
- WHEN в начальном примере включен фильтр «готовые»
- THEN видно только «Чтение», а показатели не меняются.

### Requirement: Читаемый интерфейс
Интерфейс MUST оставаться читаемым на ширине 390 px
без горизонтального скролла.
Поля и кнопки MUST иметь понятные подписи.

#### Scenario: Узкий экран
- WHEN ширина области просмотра равна 390 px
- THEN поля, кнопки, задачи и показатели доступны
  без горизонтального скролла.

## OPTIONAL Requirements

### Requirement: Сохранение задач
Если реализовано сохранение, приложение MUST сохранять
изменения задач в localStorage и восстанавливать их при открытии.
Сохраненный пустой список MUST восстанавливаться как пустой.

#### Scenario: Повторное открытие
- WHEN задачи изменены и страница открыта повторно
  при доступном хранилище
- THEN восстановлены сохраненные задачи.

#### Scenario: Недоступное хранилище
- WHEN чтение или запись localStorage недоступны
- THEN видно понятное сообщение, а приложение продолжает
  работать с задачами в памяти.
